# 阳光照明日线“三卖”时间错位核查与修正

**结论：历史笔级代理结构能复现，但实时核对与确认标记的时间含义存在问题。它不是2026年11月10日新出现的三卖。**

先按用户要求在D:/stock-dashboard完成本地核查；随后用户明确要求“上传”，本次以2026.11.10.6发布同一修正。本机复核地址 http://127.0.0.1:8850/?symbol=sh600261&period=day&data=live ，线上回归检查针对阳光照明日线及2017-10-27的6.18元对象。

## 图里这个对象是什么

截图指向的对象是`ps:third_sell:pc:4022:4041:4136`，股票阳光照明sh600261、日线、笔级代理：

| 时间或数值 | 本地查到的事实 |
|---|---|
| 价格锚点 | 2017-10-27 15:00，反抽最高6.18元，原始日线索引4136 |
| 笔级代理中枢 | 核心区间6.49—6.57元，起始范围2017-05-11—2017-06-09 |
| 离开段 | 2017-08-28的6.55元，向下到2017-10-19的6.07元 |
| 首次回试 | 6.07元反抽到6.18元，仍低于中枢下沿6.49元 |
| 首次前缀规则确认 | 2017-11-07收盘，索引4143；2017-11-06前缀还没有该点 |
| 截图中的2026-11-10 09:27:54 | 当次服务首次核对该历史点的时间，不能当成历史首次确认或今天新信号 |

第三类卖点的研究结构是向下离开中枢后的第一次回拉不返回核心。本例按笔级代理规则可以复现这个关系；笔级重叠并不等于已严格认证的完整次级别走势类型。

该规则用6.49元作为失效边界。在本次原始、未复权数据中，自2017-10-27后的已收盘日线最高6.16元，未触及6.49元，因此这个老对象仍被保留。这只表示历史结构没有触发这一个价格失效条件，不表示九年后仍应据它发出卖出指令。未认证的分红送转/复权跳变可能影响跨年的价格比较，需要另行核验，不能把本次结果声称为原文全部等价。

## 错误链条

1. `make_panel`对全历史计算结构，再把所有通过当前快照检查的对象写入confirmations，使用`now`作为confirmed_at。
2. `observed_index`被设为最新已收盘日线索引6327，所以2017年的对象会在2026年11月9日附近多画一个确认菱形。
3. 画图菱形纵坐标使用确认位置的日K收盘价，旁边显示的6.18元却是2017年价格锚点。它们是不同含义的坐标；原界面未充分区分，会让人以为当前价格产生了三卖。
4. 原始对象的`confirmation_semantics`虽然说明只是当前核对，图中文字仍直接写“确认三卖”，不足以消除误导。

截图中的灰色当天日K是形成中行情，日线未收盘，不能作为新日线结构确认的依据。

## 本地修正

- 首次加载历史只记录snapshot_audit，明确显示“历史结构核对”、结构证据K线时间、首次/本次核对时刻，不伪造confirmed_at，不画当前确认菱形。
- 只有运行期间新增闭合K线带来的新证据，才记录live_closed_bar_transition。重复刷新、服务重启、旧历史对象重新出现在窗口里都不能变成新增确认。
- 确认坐标按实际证据时间查找K线，滑动历史窗口不复用旧数值索引。旧格式current_observation确认即使再次载入，也不画成当前确认。
- 价格锚点与证据/事件时刻分列，证据面板说明两种坐标；统计分开列“事件确认”“历史核对”“失效/撤回”。提醒过滤首次历史核对，避免旧对象冒充新信号。
- 保留分型、笔、段、中枢及买卖点的计算规则；历史逐根回放未用当前时间重写，原始6.18元锚点保持不变。
