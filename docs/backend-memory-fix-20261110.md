## 问题和修正

上一版在每轮实时预览中把两个完整历史结构保留在缓存，再深拷贝给请求；成形/形成中分析同时存在，加上独立工作台与成交回测各有自己的线程/缓存，多个访问者共享512MiB实例时没有统一分配控制。

修正采用一个跨实时图、信号监控、历史面板、后台回测、独立工作台的重计算门。一个大任务运行时，同线程嵌套调用正常，其他网页请求快速返回429/Retry-After10秒，现有页面自动重试；健康检查不经过该门，继续可用。回测结果序列化/落盘也包含在预算内，完成后不保留大detail对象。

结构缓存只保存压缩pickle字节，最多8MiB，解压后对象独立；构建新模型前先移出旧缓存。实时panel缓存保存压缩JSON且只保留一份、最多8MiB。工作台回放完成后把session和结果压缩冻结，不在内存常驻扩展图，最大1个session。计算结束主动回收循环引用并在Linux上请求allocator释放可回收页。

保留完整可得历史、实时形成中预览、原有确认条件与真实源。繁忙不会返回旧快照伪装实时。未改免费套餐、未增加费用或内存上限。

## 验证

相同24,000根分钟历史的本机独立进程测量：旧版混合day/5m/15m/5m序列峰值304.55MiB，最终GC后仍242.86MiB；压缩缓存版本峰值237.13MiB，最终GC后109MiB。此为Windows本地对照，不能直接替代Linux容器验证。

scripts/stress_hosted_memory.py通过真实FastAPI路由，使用已保存的真实TDX OHLC全量数据（日期冻结，作为测试输入）、完整形成中预览和并发请求。检查一个大5分钟历史请求成功，3个并发大请求快速429，健康检查<3秒，再交替多个股票周期重复请求，并运行独立工作台回放与后续大请求，核对缓存只保留压缩字节。

CI新增真正--memory=512m --memory-swap=512m容器检查，要求Python峰值<450MiB并保持健康。测试详情、平台内存和部署/公网验收以备份目录最终VERIFICATION.txt为准，不把尚未执行检查写成成功。
